# SCORM Studio — project guide for Claude Code

## What this is

SCORM Studio is a browser-based course builder made by Keith for his security team at Global (UK).
Authors build short training courses and download them as **SCORM .zip packages to upload to Bridge**
(the Bridge LMS / e-learning platform). It runs three ways:

1. **Hosted on Keith's TrueNAS** at `https://scorm-studio.g-security.uk/` (behind a Cloudflare Tunnel).
   This is the main way colleagues use it. The same server writes quiz questions with Claude.
2. **As a single .html file** opened straight from disk on any Windows or Mac browser.
3. **As a claude.ai Artifact** (Keith's private copy), where the quiz generator uses his own Claude account.

## Working with Keith

- Give **complete replacement files**, never "find this line and change it" snippets.
- Use **plain English**, not jargon. Explain simply when asked.
- Prefer concrete outputs (working files, scripts) over abstract advice.
- When sending him updated files for the server, keep the exact names `server.js` and `scorm-studio.html`.

## Commands

```bash

npx playwright install chromium   # once, for the browser tests
npm run build               # build dist/ and refresh deploy/truenas/app/
npm run serve               # build, then run locally at http://localhost:8787 with fake questions
```

The app itself has **no build-time dependencies**. Libraries load at runtime from cdnjs, pinned:
JSZip 3.10.1 (zip export/import, docx/pptx reading) and pdf.js 3.11.174 (loaded only when a PDF is imported).

## How the builder page works (src/scorm-studio.html)

One file: CSS, markup, then one big script in an IIFE. Key areas (search for these names):

- **Config:** `STUDIO_CONFIG` at the top (`proxyUrl`, `accessCode`, `apiKey`, `model`). The server rewrites
  `proxyUrl` to `location.origin` when it hosts the page, so hosted users only type the access code.
- **State:** a single `state` object, saved to `localStorage` key `scorm-studio-draft-v1`.
  AI settings are separate in `scorm-studio-ai-v1`. Video files live in IndexedDB `scorm-studio` / `videos`.
- **Editor views:** `render()` switches on `sel.type`: `renderSettings`, `renderDesign`, `renderPage`, `renderQuiz`.
- **Page blocks:** a page is a heading plus an ordered list of typed content blocks, not a fixed
  heading+body+image+video+keypoint shape. Block `type`s: `"text"` (`body`, same markdown-lite as before),
  `"image"` (`image`, `imageAlt`, `imagePos: "standard"|"banner"`), `"video"` (`video`, same shape as always —
  `{kind:"file"|"embed"|"remote", ...}`), `"quote"` (`text`, `cite`), `"keypoint"` (`text`, `tone` — the old
  key-point callout, now placeable anywhere and more than once per page). `newBlock(type)` creates one,
  `blockEditor(b, p, redraw)` is the shared editor card (reuses the same up/down/delete pattern as
  `questionCard`), `blockHTML(b, bi)` in `PLAYER_JS` renders one for the learner. `renderImgBox`/`renderVideoBox`
  are reused unchanged for image/video blocks — they already operated generically on whatever object holding
  `.image`/`.imageAlt`/`.imagePos` or `.video` was passed in, they just used to be called on the page itself.
  **A page can now hold more than one image or video**, so anything that export/import/housekeeping code
  previously keyed by page index (image/video filenames, `cmi`-adjacent lookups) is keyed by block id instead
  — `videoBlocksOf(p)` / `allVideos()` walk every page's video blocks for housekeeping (orphan video cleanup,
  the Videos stat, project save/open). Required-video gating in `PLAYER_JS` (`showPage()`) now waits for every
  required video block on the page, not just one.
- **Migration:** `migratePageToBlocks(p)`, called from `ensureDesign()`, converts a page still in the old flat
  shape (`body`/`image`/`imageAlt`/`imagePos`/`keyPoint`/`callout`/`video` directly on the page) into blocks
  the first time it's loaded, then deletes the old fields. This is the one-time safety net for every course
  saved before the block system existed — **don't reintroduce a flat page field without also deciding what
  happens to pages that still only have `blocks`.**
- **Question cards:** `questionCard(q, qi, list, redraw)` is shared by the final quiz and per-page knowledge checks.
  Each question has a `type`: `"mc"` (default, also used for quick true/false — a UI shortcut, not a separate
  type), `"match"` (`pairs: [{left,right}]`), `"fill"` (`text` with `___` blanks + `answers: [...]`, matched
  case-insensitively), or `"hotspot"` (`image`, `imageAlt`, `zones: [{x,y,w,h,correct}]` as 0-100 percentages).
  `cleanQ(q, hotspotMap)` is the single place that shapes a question for export — **a new field on a question
  type must be added there too, or it's silently dropped from the built course.** The learner-side
  rendering/grading/wiring for all four types is shared between the final quiz and knowledge checks via
  `qBody()`, `qWire()`, `qAnswered()` and `qCorrect()` in `PLAYER_JS`.
  - Matching is a drag-and-drop-with-lines UI (SVG lines between left/right items, real pointer drag or
    click-one-then-the-other, native `<button>`s so Tab + Enter/Space also work).
  - Hotspot is click-the-image, plus an "Or choose an area" list of plain buttons (one per drawn zone) as a
    keyboard/screen-reader path, since clicking a point on an image has no natural keyboard equivalent.
    Hotspot images go through their own export path: `buildZip()`'s `exportHotspotImages()` writes each one
    to `media/hotspot-<question id>.<ext>` (page images and design assets have their own similar, separate
    paths — there's no single shared "export an image" helper).
  - **Both `qWire()`'s match `redraw()` and the hotspot click/button handlers directly touch the DOM
    (toggling `.connected`, moving a `.hs-pick` dot) after calling `setPicked()`, because `qBody()` only bakes
    classes/markers into the initial HTML string once. A new way of mutating `picked` for either type must do
    the same, or the UI silently goes stale after the first interaction** (this exact bug was caught and
    fixed twice while building these two types).
- **Validation before export:** `problems()`.
- **Quiz writing:** `buildPrompt(req)` + `writeQuestions(req, signal)`. Routes (in `aiRoute()` order):
  claude.ai `sample` capability → quiz server (`proxyUrl` + `/generate`) → direct API key (testing only).
  `cleanGenerated()` validates and shuffles answers. **`buildPrompt` is duplicated in server/server.js — keep both in step.**
- **Page drafting:** `draftBox(b, p, ta)` is the "Draft with AI" panel on a text block's editor card (`blockEditor`'s
  `b.type==="text"` branch). Same shape as quiz writing: `buildDraftPrompt(req)` + `writeDraft(req, signal)` go
  through the same `aiRoute()`/proxy `/draft` route/direct-key paths and the same AI settings, so there's nothing
  separate to set up. `req` is `{title, heading, body, mode, instruction}` — `mode` is `"expand"|"tighten"|"simplify"|"polish"`,
  `instruction` is a short optional free-text addition (bounded server-side, same pattern as `focus` on quiz writing).
  Requires at least 10 characters already in the block (it rewrites/extends what's there, it doesn't invent a page
  from nothing). The result sits in a preview with **Discard**/**Use this** — never overwrites `b.body` until the
  author clicks Use this. **`buildDraftPrompt` is duplicated in server/server.js — keep both in step** (same as `buildPrompt`).
- **Learner player:** `courseData()` + `designData()` → `playerHTML(data)` which inlines `PLAYER_CSS` and
  `PLAYER_JS`. `PLAYER_JS` is written as a function then stringified, so **it cannot use anything from the
  builder's scope**; it only reads the JSON course data embedded in the page.
- **Export:** `buildZip()` writes `index.html`, `imsmanifest.xml`, and `media/` (block images/videos as
  `page-<n>-<block position>.<ext>`, hotspot question images, logo, cover — each has its own small export loop,
  there's no single shared "export an image" helper). `manifest(files)` writes SCORM 1.2 or 2004 4th Edition
  manifests.
- **Import:** `readOffice()` → `parseDocx` (Heading 1 splits pages), `parsePptx` (one page per slide, biggest
  picture, optional speaker notes, hidden slides skipped), `parsePdf` (auto / picture / text modes;
  repeated headers, footers and page numbers stripped).
- **Saving files:** `saveFile()` uses the claude.ai `downloads` capability when present, otherwise a normal
  browser download (`plainDownload`). Project files are `.scorm-project.zip` (project.json + videos/).

### Course data shape

```js
state = {
  title, description, author,
  scorm: "1.2" | "2004",
  passMark: 0-100, showAnswers, allowRetry, shuffle, showBadge,  // showBadge: completion badge on finish, defaults true
  accent,                         // kept in sync with design.accent for older code paths
  design: {
    theme: "clean"|"deepblue"|"corporate"|"bold"|"warm"|"friendly"|"contrast"|"slate"|"mono"|"forest"|"coral"|"custom",
    accent, bg, card, text,       // hex colours
    headingFont, bodyFont,        // keys of FONTS
    header: "light"|"brand", width: "narrow"|"standard"|"wide",
    corners: "rounded"|"square", textSize: "standard"|"large",
    logo, logoAlt, cover, coverImage, coverButton   // logo/coverImage are data: URLs
  },
  pages: [{
    id, heading,
    blocks: [Block],               // see "Page blocks" above - a page used to be one fixed shape, now it's this
    check: {on, mustPass, questions:[Question], branch: {pass: pageId|null, fail: pageId|null}}
                                   // branch targets a page's *id*, not its index, so reordering pages
                                   // doesn't break them. fail only applies when mustPass is off - a
                                   // must-pass check never "fails forward", it just keeps retrying.
  }],
  quiz: [Question]
}
// Block = {id, type: "text"|"image"|"video"|"quote"|"keypoint", ...type-specific fields (see "Page blocks" above)}
// Question = {id, q, feedback, type: "mc"|"match"|"fill"|"hotspot", ...type-specific fields (see questionCard above)}
```

`ensureDesign(s)` fills in missing design fields, page defaults, `showBadge`, and defaults every question's
`type` to `"mc"` if missing. **Run it on anything loaded** (saved drafts and opened projects) so older
courses keep working.

### SCORM behaviour (in PLAYER_JS)

- Finds the LMS API by walking `window.parent` and `window.opener` (works for Bridge's popup and
  "Current window" modes). Tries 1.2 (`API`) or 2004 (`API_1484_11`) first depending on the package.
- Always reports a completion status (Bridge requires it).
  No quiz → `completed` on the last page. Quiz → score + `passed`/`failed` against the pass mark.
- Bookmark: `cmi.core.lesson_location` / `cmi.location` = page index.
- `cmi.suspend_data` JSON: `v` visited pages, `w` watched required videos, `k` passed knowledge checks,
  `f` finished, `s` last score. SCORM 1.2 caps suspend_data at 4096 characters, so keep it small.
- Session time written on exit; `cmi.core.exit` / `cmi.exit` = `suspend` until finished.
- Knowledge checks never count towards the score. Must-pass checks keep right answers locked on retry.
- Branching: `pageIndexById(id)` resolves a check's `branch.pass`/`branch.fail` page id to an index;
  `gotoOrAdvance(targetId)` jumps there if found, else falls through to the normal `advance()`. Wired into
  the "Continue" button in `showCheck()`. The final quiz is never branch-driven - it always runs last.

## The quiz server (server/server.js)

Plain Node 18+, no packages. Env vars: `ANTHROPIC_API_KEY`, `ACCESS_CODE` (8+ chars), `MODEL`
(default `claude-sonnet-5-5`), `PORT` (8787), `LIMIT_PER_HOUR` (20 per IP), `LIMIT_PER_DAY` (100 total),
`MAX_QUESTIONS` (15), `HTML_FILE`, `API_URL` (tests only), `TRUST_PROXY` (0/unset by default).

Routes: `GET /` (page, re-read when the file changes), `GET /ping` (no code), `GET /health` (checks code,
shows requests left), `POST /generate` (needs `X-Access-Code`), `POST /draft` (needs `X-Access-Code`, drafts/rewrites
a page's text, shares the same per-IP/per-day limits as `/generate` — not a separate budget), `/favicon.ico` → 204,
`HEAD` supported, CORS open. `readBody()`/`askClaude()` hold the body-size guard and upstream-error handling shared
by both POST routes, so a fix to one applies to both.
Security: constant-time code compare, 15-minute lockout after 10 wrong codes per IP (pruned every 10 min),
600 KB body cap, the server builds the prompt itself (no free-form chat), logs counts and tokens only
(never course text).
Real client IP: `cf-connecting-ip` is always trusted (only set by the real Cloudflare Tunnel). `x-forwarded-for`
is only trusted when `TRUST_PROXY=1` — it's client-supplied otherwise, so trusting it by default would let
anyone spoof a different IP per request and dodge the per-person rate limit.

## Deploying to TrueNAS (Keith's server)

TrueNAS Community Edition 25.04, custom app via **Apps > Discover Apps > ⋮ > Install via YAML**,
app name `scorm-studio`, container `ix-scorm-studio-scorm-studio-1`, image `node:22-alpine`, user `568:568`,
dataset mounted read-only at `/app`, port 8787, public via the Cloudflared app.

Update procedure (tell Keith exactly this):
1. `npm run build`, then send him `deploy/truenas/app/scorm-studio.html` and/or `server.js`.
2. He copies them straight into the dataset (not a subfolder), then runs in System > Shell:
   ```bash
   P=$(sudo docker inspect -f '{{range .Mounts}}{{.Source}}{{end}}' ix-scorm-studio-scorm-studio-1)
   sudo chown 568:568 "$P"/* && sudo chmod 644 "$P"/*
   ```
3. `scorm-studio.html` needs no restart. `server.js` needs Apps > scorm-studio > Restart.

Full guide and troubleshooting: `docs/TRUENAS-SETUP.md`.

## Testing rules

- Run `npm test` before handing anything over. Browser tests use Playwright Chromium.
- For visual changes, take screenshots with Playwright and look at them (desktop 1440 and phone 390 wide).
- Never call the real Claude API in tests; use the mock in tests or `npm run serve`.
- The page must stay one self-contained file (only cdnjs scripts and Google Fonts load from outside),
  because it also runs as a claude.ai Artifact under a strict content policy.

## Decisions already made (don't revisit without Keith)

- Bridge accepts SCORM 1.2 and 2004 only (no xAPI/cmi5). Default export is SCORM 1.2.
- There is no free Claude API. Questions use Keith's API key **behind the server**; never ship a key in the page.
- Workspace spend limit on the Claude Console is the cost safety net, plus the server's limits.
- Bridge opens SCORM in a popup by default; authors change **More Settings > Opens in > Current window**.
- Fonts: web fonts load from Google Fonts at runtime with standard fallbacks.
