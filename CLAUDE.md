# SCORM Studio — project guide for Claude Code

## What this is

SCORM Studio is a browser-based course builder made by Keith for his security team at Global (UK).
Authors build short training courses and download them as **SCORM .zip packages to upload to Bridge**
(the Bridge LMS / e-learning platform). It runs three ways:

1. **Hosted on Keith's TrueNAS** at `https://scorm-studio.g-security.uk/` (behind a Cloudflare Tunnel).
   This is the main way colleagues use it. The same server writes quiz questions with Claude.
2. **As a single .html file** opened straight from disk on any Windows or Mac browser.
3. **As a claude.ai Artifact** (Keith's private copy), where the quiz generator uses his own Claude account.

## How the builder page works (src/scorm-studio.html)

One file: CSS, markup, then one big script in an IIFE. Key areas (search for these names):

- **Config:** `STUDIO_CONFIG` at the top (`proxyUrl`, `accessCode`, `apiKey`, `model`). The server rewrites
  `proxyUrl` to `location.origin` when it hosts the page, so hosted users only type the access code.
- **State:** a single `state` object, saved to `localStorage` key `scorm-studio-draft-v1`.
  AI settings are separate in `scorm-studio-ai-v1`. Video files live in IndexedDB `scorm-studio` / `videos`.
- **Editor views:** `render()` switches on `sel.type`: `renderSettings`, `renderDesign`, `renderPage`, `renderQuiz`.
- **Question cards:** `questionCard(q, qi, list, redraw)` is shared by the final quiz and per-page knowledge checks.
- **Validation before export:** `problems()`.
- **Quiz writing:** `buildPrompt(req)` + `writeQuestions(req, signal)`. Routes (in `aiRoute()` order):
  claude.ai `sample` capability → quiz server (`proxyUrl` + `/generate`) → direct API key (testing only).
  `cleanGenerated()` validates and shuffles answers. **`buildPrompt` is duplicated in server/server.js — keep both in step.**
- **Learner player:** `courseData()` + `designData()` → `playerHTML(data)` which inlines `PLAYER_CSS` and
  `PLAYER_JS`. `PLAYER_JS` is written as a function then stringified, so **it cannot use anything from the
  builder's scope**; it only reads the JSON course data embedded in the page.
- **Export:** `buildZip()` writes `index.html`, `imsmanifest.xml`, and `media/` (page images, videos, logo, cover).
  `manifest(files)` writes SCORM 1.2 or 2004 4th Edition manifests.
- **Import:** `readOffice()` → `parseDocx` (Heading 1 splits pages), `parsePptx` (one page per slide, biggest
  picture, optional speaker notes, hidden slides skipped), `parsePdf` (auto / picture / text modes;
  repeated headers, footers and page numbers stripped).
- **Saving files:** `saveFile()` uses the claude.ai `downloads` capability when present, otherwise a normal
  browser download (`plainDownload`). Project files are `.scorm-project.zip` (project.json + videos/).

### Course data shape

```js
state = {
  title, description, author,
  scorm: "1.2" | "2004",
  passMark: 0-100, showAnswers, allowRetry, shuffle,
  accent,                         // kept in sync with design.accent for older code paths
  design: {
    theme: "clean"|"deepblue"|"corporate"|"bold"|"warm"|"friendly"|"contrast"|"custom",
    accent, bg, card, text,       // hex colours
    headingFont, bodyFont,        // keys of FONTS
    header: "light"|"brand", width: "narrow"|"standard"|"wide",
    corners: "rounded"|"square", textSize: "standard"|"large",
    logo, logoAlt, cover, coverImage, coverButton   // logo/coverImage are data: URLs
  },
  pages: [{
    id, heading, body,            // body: blank line = paragraph, "- " = bullet, **bold**
    image, imageAlt,              // image: data: URL
    imagePos: "above"|"below"|"left"|"right"|"banner",
    keyPoint, callout: "brand"|"info"|"warning"|"success"|"danger",
    video: null | {kind:"file", key, name, type, size, required}
                | {kind:"embed", url, src, site} | {kind:"remote", url, src, site, required},
    check: {on, mustPass, questions:[{id, q, options:[...], correct, feedback}]}
  }],
  quiz: [{id, q, options:[...], correct, feedback}]
}
```

`ensureDesign(s)` fills in missing design fields and page defaults. **Run it on anything loaded**
(saved drafts and opened projects) so older courses keep working.

### SCORM behaviour (in PLAYER_JS)

- Finds the LMS API by walking `window.parent` and `window.opener` (works for Bridge's popup and
  "Current window" modes). Tries 1.2 (`API`) or 2004 (`API_1484_11`) first depending on the package.
- Always reports a completion status (Bridge requires it).
  No quiz → `completed` on the last page. Quiz → score + `passed`/`failed` against the pass mark.
- Bookmark: `cmi.core.lesson_location` / `cmi.location` = page index.
- `cmi.suspend_data` JSON: `v` visited pages, `w` watched required videos, `k` passed knowledge checks,
  `f` finished, `s` last score. SCORM 1.2 caps suspend_data at 4096 characters, so keep it small.
- Session time written on exit; `cmi.core.exit` / `cmi.exit` = `suspend` until finished.
- Knowledge checks never count towards the score. Must-pass checks keep right answers locked on retry.

## The quiz server (server/server.js)

Plain Node 18+, no packages. Env vars: `ANTHROPIC_API_KEY`, `ACCESS_CODE` (8+ chars), `MODEL`
(default `claude-sonnet-5-5`), `PORT` (8787), `LIMIT_PER_HOUR` (20 per IP), `LIMIT_PER_DAY` (100 total),
`MAX_QUESTIONS` (15), `HTML_FILE`, `API_URL` (tests only), `TRUST_PROXY` (0/unset by default).

Routes: `GET /` (page, re-read when the file changes), `GET /ping` (no code), `GET /health` (checks code,
shows requests left), `POST /generate` (needs `X-Access-Code`), `/favicon.ico` → 204, `HEAD` supported, CORS open.
Security: constant-time code compare, 15-minute lockout after 10 wrong codes per IP (pruned every 10 min),
600 KB body cap, the server builds the prompt itself (no free-form chat), logs counts and tokens only
(never course text).
Real client IP: `cf-connecting-ip` is always trusted (only set by the real Cloudflare Tunnel). `x-forwarded-for`
is only trusted when `TRUST_PROXY=1` — it's client-supplied otherwise, so trusting it by default would let
anyone spoof a different IP per request and dodge the per-person rate limit.

## Deploying to TrueNAS (Keith's server)

TrueNAS Community Edition 25.04, custom app via **Apps > Discover Apps > ⋮ > Install via YAML**,
app name `scorm-studio`, container `ix-scorm-studio-scorm-studio-1`, image `node:22-alpine`, user `568:568`,
dataset mounted read-only at `/app`, port 8787, public via the Cloudflared app.

Update procedure (tell Keith exactly this):
1. `npm run build`, then send him `deploy/truenas/app/scorm-studio.html` and/or `server.js`.
2. He copies them straight into the dataset (not a subfolder), then runs in System > Shell:
   ```bash
   P=$(sudo docker inspect -f '{{range .Mounts}}{{.Source}}{{end}}' ix-scorm-studio-scorm-studio-1)
   sudo chown 568:568 "$P"/* && sudo chmod 644 "$P"/*
   ```
3. `scorm-studio.html` needs no restart. `server.js` needs Apps > scorm-studio > Restart.

Full guide and troubleshooting: `docs/TRUENAS-SETUP.md`.

## Testing rules

- Run `npm test` before handing anything over. Browser tests use Playwright Chromium.
- For visual changes, take screenshots with Playwright and look at them (desktop 1440 and phone 390 wide).
- Never call the real Claude API in tests; use the mock in tests or `npm run serve`.
- The page must stay one self-contained file (only cdnjs scripts and Google Fonts load from outside),
  because it also runs as a claude.ai Artifact under a strict content policy.

## Decisions already made (don't revisit without Keith)

- Bridge accepts SCORM 1.2 and 2004 only (no xAPI/cmi5). Default export is SCORM 1.2.
- There is no free Claude API. Questions use Keith's API key **behind the server**; never ship a key in the page.
- Workspace spend limit on the Claude Console is the cost safety net, plus the server's limits.
- Bridge opens SCORM in a popup by default; authors change **More Settings > Opens in > Current window**.
- Fonts: web fonts load from Google Fonts at runtime with standard fallbacks.
